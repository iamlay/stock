> 验证日期：2026-10-27（Asia/Shanghai）。
> 状态：本地技术验证及交付物已完成；**V2-48 整体验收未通过**。

## 1. 本次结论与允许范围

可以进入 V2-49 的事件版本模型、兼容接口及人工核对原型开发；不得据此开启自动个人分红权益、自动到账或对外承诺完整派息日历。V2-50 的数据隔离/隐私基础可按已有明确需求开发，真实产品激活及付费验证仍需用户反馈。

当前公开接口适合作为待核对的分红线索，不足以独立作为个人收息账本的完整事实来源：

1. 有 `EQUITY_RECORD_DATE`，现有 `DividendRecord` / `StockDividend` 未保存该字段。
2. 本次 40 条记录的响应字段没有明确的现金红利发放日；不能令派息日等于除息日。
3. 响应没有可验证的单次分红事件 ID、生命周期修订链或实施公告链接。`SECURITY_INNER_CODE` 是证券身份，不是分红事件身份。
4. 样本中有两条预披露方案，无确定金额和权益日期；现有 `parse_dividends` 会丢弃金额缺失或非正的记录，不能用该解析结果验证取消/零分红的覆盖。
5. `BONUS_RATIO` / `IT_RATIO` 在本次样本均为空，不能仅因空值认定没有送股/转增。
6. 一次联网成功只能证明本次观察可获取；不能证明完整历史、生产服务可用性、更新延迟或商业授权。

## 3. 字段字典和映射（契约 v2-48.1）

“已观察”表示快照存在且能够解析；“待验证”不得自动填值。下表为 V2-49 的输入契约，新增数据库名与迁移由 V2-49 的 ADR 冻结。

| 原字段 | 规范字段/单位 | 当前情况与约束 |
|---|---|---|
| `SECURITY_CODE` + `SECUCODE` | 标的代码及市场 | 证券身份；未来跨市场使用市场+代码，不以代码单独跨市场去重 |
| `SECURITY_NAME_ABBR` | 展示名 | 非事件身份，改名不建新分红 |
| `SECURITY_INNER_CODE` / `ORG_CODE` | 证券/机构线索 | 不映射为分红事件 ID |
| `REPORT_DATE` | `report_date` / ISO 日期 | 分红利润所属报告期，不是实际到账日；同年中期/年度/其他轮次分别保存 |
| `NOTICE_DATE` | 来源当前披露日 | 非抓取时间，也不代表历史首次公告日或修订序号 |
| `PLAN_NOTICE_DATE` | 方案首次披露候选日 | 保留原值；不作为稳定唯一身份 |
| `PRETAX_BONUS_RMB` | 每 10 股税前人民币 | Decimal 除以 10 得每股；缺失、非数、负值保留未知；零不直接当解析失败或丢弃事件 |
| `IMPL_PLAN_PROFILE` | 原分配文本 | 原样保存，不从“扣税后”文本推断用户实收税率，不从“特别”关键词直接冻结正式分类 |

| `EX_DIVIDEND_DATE` | `ex_date` / ISO 日期 | 除息日，不能代替派息日 |
| `ASSIGN_PROGRESS` | 来源阶段 + 规范阶段 | 原文和映射版本都保留，未知状态隔离；不按日历自动晋级 |

| 无已验证字段 | `announcement_url` | 由公告身份和匹配结果补充，不能直接把列表 API URL 冒充公告链接 |
| 采集器生成 | `observed_at`、请求 URL、原始行哈希 | 精确记录采集证据；与公告时间、事件修订时间分别存储 |
| `EX_DIVIDEND_DAYS`、估值、股价变化等 | 非事件核心字段 | 可能随时间变动，不参与 V2-49 的分红核心修订指纹 |

### 3.1 阶段和生命周期

探针只对明确值做候选映射：董事会预案 → proposed；股东大会通过 → approved；实施分配 → implemented；取消/终止分配 → cancelled；不分配 → no_distribution。除“实施分配”外，本次未对这些候选逐一取得真实生命周期证据，不能把测试输入视为上游已验证枚举。

实际观察到的“预披露”保持 unknown，并保留原文；它不等于明确董事会每股金额预案。V2-49 可在补证后新增 disclosed 分类。未知、新增或包含取消词的组合状态都进入待核对，禁止用“包含实施”之类宽松匹配升级。

取消或零分红必须保存事件；不能靠现有“现金金额大于零才保留”的研究解析器构建事件生命周期。第一页没有出现旧事件，不代表该事件已取消。

### 3.2 事件身份和修订规则

1. 内部事件使用不随更正变化的主键，按实际分红轮次建身份；来源 ID 可空，不能以空字符串充当唯一值。
2. 公告 ID 标识一份公告，不当然标识方案全生命周期；董事会、股东会、实施和更正公告可关联同一内部事件，并分别保留身份与证据。
3. `市场/股票/报告期/轮次` 是关联线索；报告期、金额、日期、方案文字会变化或冲突，不能单凭它们无条件更新已有事件。
4. 没有来源身份时，只有在公告关系和轮次可唯一确认时才自动关联；不明确进入待复核清单，不覆盖旧行，不合并同年两次派息。
5. 核心修订比较金额、三类日期、阶段、现金/送转组成及来源关系；排除动态距离天数、收益率等无关字段。原始行哈希用于溯源，不作为修订号。
6. 重复抓取不创建新核心版本；历史版本不可覆写。更正涉及已确认实收时仅生成差异待办，不篡改用户原始到账。

## 4. 计算口径冻结与人工模式

- 首版只支持人民币普通现金分红，税前应收采用登记日收盘已知合资格数量 × 本次每股现金金额；金额舍入到现金单位的方式需与后续实际入账差异分开保留。
- 期初持仓只覆盖其生效日及以后；登记日晚于/等于有效历史范围才能自动推导。登记日后的交易不改变已取得的历史权益。
- 预披露、预案、未知阶段、金额未知、登记日缺失、历史缺口、公司行动未知均不得生成正式自动应收。
- 派息日缺失时日历显示“待确定日期”；权益数学可能可算，但不得补日期或分入确定月份。完整自动化仍受总门槛限制。
- 实收按用户核对/导入的实际现金日期记录，不因系统日期到了而生成。部分到账、补扣税、冲正、未关联收入按详细方案处理。
- 文本“含税/扣税后”是方案信息，非用户个人实收证据。用户税费实际记录，不新增统一固定税率假设。
- 特别/一次性分红分类、送转字段空值必须补证；未知类型不当普通经常性分红参与确定预测。

[20 个产品算例](evidence/v2-48/acceptance-cases.json)覆盖单位换算、精确金额、登记当日买卖、登记后卖出、除息后买入、历史缺口、预案、取消、多次分红、更正、去重、未知派息日、部分到账、补扣税、跨年归属、未知公司行动、预披露、历史负仓以及非自动到账。

人工模式：用户从已核对公告补录日期/方案，明确“人工提供”及依据；未知持仓权益可由用户确认数量并留证；可先记未关联实际收入再关联。人工输入仍是私人记录，不写成全站已认证市场数据，也不自动适用于其他用户。

## 5. 历史覆盖、时效与来源使用条件

| 验证项 | 本次结果 | 放行所需证据 |
|---|---|---|
| 本次可获取性 | 4/4 请求成功，40 条记录 | 失败/重试、分页及持续观察，不据单次成功承诺 SLA |
| 历史完整性 | 仅每股最近 10 条，最早报告日 2018-12-31 | 明确历史区间、分页及至少一个公司完整年度序列与公告对账 |
| 缺日期/预披露 | 2 条真实缺日期及金额记录 | 已证明需要未知状态；后续规则不得补假值 |
| 同年多次分红 | 多个股票/年份存在多条 | 补公告确认轮次与事件对应，不按年份唯一合并 |
| 更正/取消 | 没有取得真实成对修订/取消样本 | 每类至少一组原公告及后续公告，人工确认身份与金额/阶段变化 |
| 派息日 | 结构化响应缺字段；1 份实施公告可取得 | 至少覆盖本次抽样事件的公告日期核对和无法取得清单 |
| 更新时效 | 单次采集，未知源更新时间 | 连续至少 7 个自然日重复采样，含一个新公告事件，记录首次可见与公告时间；仍说明样本局限 |
| 商业数据使用 | 未找到/未获得可证明许可 | 负责人核实来源条款、可否采集/缓存/商用/再分发，保存核实时间与依据；API 可访问不等于授权 |
| 真实用户需求 | 访谈 0/10–15 人 | 负责人提供脱敏实际访谈与首版取舍确认 |

当前 `Stock Dividends` workflow 配置为每周一 19:00（Asia/Shanghai）刷新，另有手动全量入口；它不能证明新公告会及时进入收息提醒，GitHub 定时触发本身也不是源数据 SLA。五分钟行情更新不等于五分钟分红更新。本任务不改生产调度；V2-56 根据补充观测再冻结唯一调度入口、日内复查和延迟提示。

## 6. 复现方式与退出码

在仓库根目录使用已安装 Python 环境：

```bash

# 离线重放已提交快照，不联网、不使用数据库

# 只运行本任务测试和静态检查
python -m pytest apps/api/tests/test_dividend_probe.py -q
python -m ruff check etl/dividend_probe.py apps/api/tests/test_dividend_probe.py
```

退出码 0 仅表示探针取得至少 30 条不同原始行且采样无请求失败，不表示业务验收通过；结果中 `assessment=blocked_for_automatic_accounting` 和两个自动开关候选值始终为 false。请求失败或样本不足退出 1；失败保存在快照中便于重放。错误响应/混入其他股票的响应不当成成功样本；输入参数有界，单次响应最大 5 MB，不执行任意数据库操作。

`--output` 会写入/覆盖目录中的 `snapshot.json` 和 `report.json`；新增观测请使用新目录，勿覆盖已提交的历史证据。线上 CI 只跑离线测试，不依赖公开接口可用性，也不安排新的生产定时任务。
