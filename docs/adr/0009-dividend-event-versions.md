# ADR-0009：分红事件版本与人工证据核对

- 日期：2026-10-27。
- 状态：V2-49 本地实现并测试，尚未部署。
- 依据：[V2-48 验证报告](../V2_48_VALIDATION_REPORT.md)、[收息管理方案](../DIVIDEND_PORTFOLIO_PLAN.md)。

## 背景

现有 `stock_dividends` 服务股票详情、TTM/RLY/年度股息率和提醒，其旧唯一键与日期/方案相关，ETL 会直接更新字段。上游没有已验证的稳定事件 ID，也缺派息日，不能把现有匹配规则直接升级为个人权益或修订历史的身份规则。

## 决策

1. 新增 `dividend_events`、`dividend_event_versions`、`dividend_source_observations`，只做增量迁移。事件 UUID 独立于日期、金额和方案文字；版本以 `(event_id, revision)` 为主键，服务只追加版本。
2. 原始来源观察保留全状态、原始 JSON、请求 URL、采集时间和规范化候选。零金额、取消、预披露和字段缺失不因不适合计算股息率而丢弃。按 `(source, code, fingerprint)` 防重复入队；指纹只覆盖分红核心字段，不包括价格、距离天数或采集时间，金额统一为 Decimal 规范字符串。
3. 没有已验证的来源身份时，不自动关联新观察和旧事件。日期、金额、方案或阶段变化进入 pending 队列，由管理员明确 create / revise / ignore。同一报告期可以存在多个事件；证券内码、报告日期、原始行哈希、公告 ID 都不直接等同于完整生命周期身份。
4. 人工核对要求说明、管理员权限和审计；revise 要求当前版本号。重复同一决策返回原结果，换决策返回冲突；更早/无日期证据覆盖已有较新证据须显式 `allow_older_evidence`。以股票父行锁统一串行化观察、回填和核对，防止首次创建及版本序号竞争；观察行额外加锁，事务内提交版本和审计。
5. 派息日无上游映射，保持 NULL；管理员补录必须提供公告 URL。修订不会自动继承上一版本的手工派息日；需要重新核对。公告 URL 仅保存和展示，不由服务端抓取。原始来源和人工覆盖后的字段分别保留。
6. 旧数据通过独立、有界、默认 dry-run 的工具回填。每个旧行得到一个 legacy_unverified 快照，不合并，不推断登记日/派息日，不冒充已公告核验。回填 UUID 按旧行身份稳定生成；重复回填不追加版本。
7. 分阶段兼容：V2-49 保留原研究表及旧接口计算口径，现有 ETL 一次抓取同时收集未过滤证据；新事件接口只供事件核对，不驱动旧股息率、旧提醒或个人应收。旧研究表后续更新不会静默覆盖事件历史；新来源变化保持 pending，接口返回未核对观察数量和证据时间。不得混合两个接口的记录相加计算分红。
8. 新事件层是后续个人收息消费的目标来源。正式切读/投影回旧研究数据前，需要 V2-48 证据、身份关联及对账通过，并在 V2-56 发布评审中确认；当前不宣称迁移已切读，也不删除旧字段。避免在过渡期把旧研究记录和新核对版本都当成同一输出的可写事实源。
9. 所有新公开结果明确返回自动权益/自动到账均为 false。本次没有生成持仓、个人应收或收款记录，不修改会员和支付规则。

## 取舍

优先保存证据及避免错误合并，代价是初期核对队列较多。不要为减少队列而按“同年/同报告期”强行匹配。数据库迁移只建表，批量回填独立执行，避免应用启动时全表写入。管理员入口为 API，操作步骤见 [V2-49 交付说明](../V2_49_DELIVERY.md)；完整运营界面独立按后续任务规划，不伪称已提供页面。
