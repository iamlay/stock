# ADR-0012：持仓快照、多成本口径与预览确认

日期：2026-10-28。状态：已实现，本地验收；生产待部署。

## 背景

V2-51以加权平均重放流水，不能把用户从券商抄来的摊薄成本当作加权成本。新版按[持仓重设计](../PORTFOLIO_ENTRY_REDESIGN.md)将已有持仓与新成交分开。

## 决策

1. 复用追加式 `portfolio_entries`、账户/用户复合外键、请求唯一键与更正关联。新增可空 `details` JSON/JSONB，保存版本化成本口径、有符号余额（十进制字符串）、原始输入模式和值、费用已知性、分组与分红参考。新增 `snapshot / rebase / preference` 类型；不改旧字段含义，不把负余额写进 `total_cost`。
2. 不再单独创建快照/设置/周期表：快照和设置是已有账户下的不可变事件；周期及三口径是确定性投影。这样导出、账户删除和恢复删除清单直接涵盖新数据，避免两套持仓账本。独立服务 `portfolio_positions.py` 管理新版规则。
3. `snapshot` 是第一份日终快照，只初始化用户明确提供的成本余额；其余口径为未知。`rebase` 是显式修正当前总持仓，要求原因及依据；替换该日余额、保留此前记账区间和原始流水，不计作买入或已实现收益。快照日已含交易，后续新增流水必须晚于该日；更早记录需更正原事实，不能在快照外叠加重复历史。
4. Cw为加权剩余成本，Ct为扣卖出净收入后的净投入，Cd再扣实际净分红。只有已知余额才向后滚动。新买入周期可知Cw/Ct，但实际到账模块尚未开放，因此不凭空初始化Cd为已确认值。已知Cd快照可随买卖更新；真实净股息更新留给V2-53，不自动生成现金收入。
5. 未填费用是估算0，明确填0才是已知0；更正费用会重放全部历史。清仓后再买入开启新周期；旧区间交易盈亏保留，不能抵扣新周期成本。修正基准亦保留此前区间。
6. 所有计算采用服务端Decimal（50位上下文、金额6位小数HALF_UP）；前端BigInt仅做即时说明。原始总额不通过舍入单价回算。新A股为整数股；旧版小数股保留、更正时沿用旧精度，绝不迁移取整。
7. `position-preview`不写入账务或确认记录。返回15分钟签名预览凭据，仅含用户/账户、输入及结果摘要、策略版本，不含持仓正文。`position-confirm`重新锁定所有者及账户、验证版本/同意/签名/结果摘要、完整历史重放后原子写入。相同请求重试返回已保存结果，不重复记账。自动同日排序在锁内完成。
8. 新增名称/代码搜索使用POST请求体，返回全部已收录A股（含非活跃），不依赖行情或高股息榜单。客户端防抖、取消旧请求、输入变化清除旧标的和相关成本，选中稳定证券身份才能提交。
9. `preference`只改变展示设置，不写分红核对范围。行情带原始时间；部分缺价显示已知市值，全部缺价显示未知。历史分红只展示当前事件版本和来源；没有完整覆盖、特别分红和送转核验，12/36/60个月自动年均保持不足，不用无数据替代0。允许个人自定义0或正数，不进入公共事件/应收/实收。
10. 私人说明升级v3，旧同意不能直接写新范围。免费导出在含新事实时标记v3并带全部details；删除和备份恢复清单清理均复用原账户外键。没有新增本地草稿、外部分析或第三方数据上传。

## 兼容和发布

- 迁移 `f1a7b9c52346` 只增量加字段和类型，不回填/覆盖旧持仓。
- 仅旧流水的 `/ledger` 重放保持旧规则；新事实使用 `positions-cny-v3`，未知成本可能为null。旧写接口对已使用新事实的账本明确要求新版入口，避免绕过预览或误写口径；已保存旧请求重试仍幂等。
- 新UI可以更正和撤销旧记录，保留旧类型和日期语义；不能借更正旧记录偷换成本口径。
- 有新details时迁移降级主动拒绝，不静默删除新成本信息。发布先迁移/API，再Web；回退应优先关闭入口并保留数据，完整回退须核对备份及删除清单。
- 真实券商脱敏完整样本、生产部署、历史覆盖资格尚未完成；不把本地算例/自动测试写成券商或生产验收。
