# ADR-0008：无经营主体阶段的商业化与登录方案

- **状态**：已接受
- **日期**：2026-10-19
- **决策人**：项目负责人
- **相关**：[开发计划第 17 节](../DEVELOPMENT_PLAN.md#17-无主体阶段的商业化方案)

## 背景

MVP 范围已锁定为 **仅 ETF**。当前项目**没有个体工商户或公司主体**，而以下三件事都依赖营业执照：

1. 微信开放平台「网站应用」扫码登录（个人主体不可申请）；
2. 微信支付 / 支付宝商户号；
3. 经营性网站备案（个人备案不得用于经营性内容）。

这不影响产品开发，但会阻塞"上线即可收费"的假设，需要在架构与运营上解耦。

## 选项

| 选项 | 说明 | 优点 | 缺点 |
|---|---|---|---|
| A. 注册个体工商户 | 线上电子营业执照，1–2 周 | 可申请微信支付、开放平台；合规路径清晰 | 需要经营场所材料、税务登记；有维护成本 |
| B. 第三方知识付费平台 | 知识星球 / 小鹅通 / 爱发电代收 | 当天可用；平台承担商户资质 | 抽成 5–10%；无法自动续费；品牌感弱 |
| C. 个人收款码 + 手工开通 | 个人转账后人工加会员 | 零成本 | 对账/退款/税务风险高；不符合经营合规 |
| D. 纯免费内测 | 不收款，先做用户 | 风险最低 | 无法验证付费意愿 |

## 决策

**采用 B + A 并行**：

- **短期（W1 起）**：第三方平台承接收款，平台生成订单后发放**兑换码**；产品内只做"邀请码 / 兑换码 + 人工开通"。
- **中期（W7–W10）**：个体户就绪后申请微信支付商户，接入 `PaymentProvider`，保留兑换码作为渠道与客服补偿。
- **登录**：MVP 仅手机号 + 短信验证码；微信扫码登录延后至主体认证通过（V1.1），不作为上线前置条件。
- **技术约束**：
  - 所有套餐与购买入口由 `PAYMENT_PROVIDER` 开关控制，`none` 时前端不展示价格与购买按钮；
  - 兑换码在数据库事务内校验并核销，防并发与重放；
  - 不接入个人收款码，不做手工改库开通（必须走后台审计）。

## 后果

**正面**

- 资质审批不再位于关键路径，上线时间可控；
- 可在 2–4 周内验证真实付费意愿，避免过度开发；
- 合规风险由持牌/有资质平台分担。

**负面**

- 平台抽成压缩毛利，且结算周期不可控；
- 无法实现自动续费与静默扣款，续费靠提醒 + 兑换码；
- 兑换码有流转与泄露风险，需要批次管理与对账；
- 用户信任度低于自有支付页。

**缓解**

- 批次化生成、绑定渠道、限制使用次数与有效期；
- 每周对账（售出 / 兑换 / 过期），差异 > 2% 即排查；
- 主体就绪后提供"老用户迁移价"，平滑切换；
- 客服话术明确"由第三方平台收款与开票"。
