# ADR-0008：无主体、无站内支付的商业化与登录方案

- **状态**：已接受
- **日期**：2026-10-19
- **决策人**：项目负责人
- **相关**：[开发计划第 17 节](../DEVELOPMENT_PLAN.md#17-无主体无站内支付的商业化方案)

## 背景

MVP 范围锁定为 **仅 ETF**，且项目**没有个体工商户或公司主体**。同时产品明确：**不提供微信登录与微信支付**。

这意味着：

1. 登录只能依赖手机号 + 短信验证码；
2. 站内不能收款，也不应保留任何支付入口（避免误导与合规风险）；
3. 会员开通必须绕开支付：由第三方知识付费平台代收，产品侧只做兑换码核销；
4. 经营性备案与开票仍受主体限制，但不阻塞产品上线。

## 选项

| 选项 | 说明 | 优点 | 缺点 |
|---|---|---|---|
| A. 注册个体工商户 | 线上电子营业执照，1–2 周 | 可开票、可企业备案，品牌信任更好 | 经营场所材料、税务与维护成本 |
| B. 第三方知识付费平台 | 知识星球 / 小鹅通代收并开票 | 当天可用；平台承担商户资质 | 抽成 5–10%；品牌感弱；结算周期不可控 |
| C. 纯免费内测 | 不收款，先做用户 | 零风险 | 无法验证付费意愿 |

> 个人收款码 + 手工开通被明确排除：对账、退款、税务均不可控。

## 决策

**采用 B（主）+ A（可选）**：

- **登录**：只做手机号 + 短信验证码；**不接入微信登录**，也不做第三方 OAuth。
- **支付**：**站内不做支付**，不接微信支付/支付宝，不实现订单、回调、退款等支付域代码。
- **会员**：第三方平台售出后发放兑换码，用户在 `/redeem` 兑换；后台可人工开通/延期，必须留审计。
- **个体户**：仅用于开票与企业备案，按需注册；注册与否不改变"站内不收款"的架构。
- **技术约束**：
  - `GET /plans` 永远返回 `purchasable=false`，前端只展示权益与"获取兑换码"；
  - 兑换码在数据库事务内校验并核销（行锁 + 唯一约束），防并发与重放；
  - 不新增 `orders`、`payments`、`refunds` 表；
  - 不接入个人收款码，不做手工改库开通。

## 后果

**正面**

- 不依赖任何支付资质，上线时间可控；
- 不碰资金，合规与对账风险最低；
- 可在 2–4 周内验证真实付费意愿；
- 少一个支付域，2 人团队的维护面积显著缩小。

**负面**

- 平台抽成压缩毛利，结算周期不可控；
- 无法自动续费，续费依赖站内信/邮件提醒 + 再次兑换；
- 兑换码有流转与泄露风险，需要批次管理与对账；
- 用户信任度弱于自有收银台。

**缓解**

- 批次化生成、绑定渠道、限制使用次数与有效期；
- 每周对账（售出 / 兑换 / 过期），差异 > 2% 即排查；
- 客服话术明确"由第三方平台收款与开票"；
- 兑换码可随时切换渠道，不被单一平台绑定。
