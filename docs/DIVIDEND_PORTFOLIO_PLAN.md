# 高股息研究与收息管理开发方案

> 制定日期：2026-10-27。状态：待开发的产品与技术设计，不代表已实现或上线。
> 任务编号、依赖、工作量和完成证据统一维护在 [主开发计划第 20 节](DEVELOPMENT_PLAN.md#20-高股息深度用户持仓收息与分红质量专项2026-10-27)。本文件维护详细规格，变更时同步主计划。

## 1. 产品目标与依据

目标用户是长期持有高股息资产、关心收入稳定性、愿意维护持仓记录的个人投资者。核心闭环：研究标的 → 记录真实持仓 → 判断分红资格 → 查看应收 → 核对到账 → 规划现金流 → 复核分红风险。

现有基础为股息率及历史分位、财务、分红历史、自选、网格/布林、提醒、回测和会员支付。当前 `StockWatchlist` 是收藏而非持仓；`StockDividend` 已有公告日、除息日、报告期、阶段和特别分红标签，但缺少完整登记/派息日期及事件修订链；`StockFinancial` 已有利润、ROE、经营现金流和负债等基础。以现有实现为起点扩展，不另建行情、支付或通知系统。

竞品参考：[息记 App Store](https://apps.apple.com/cn/app/id6771598026)，2026-10-27 核对公开介绍，非登录实测。其已覆盖持仓收息、日历、预测和基本面等方向；本项目重点验证“可信的个人收息账本 + 有证据的分红质量 + 个人收入风险”是否带来持续使用，不以功能数量判断竞争力。

### 1.1 首版范围

- A 股普通现金分红、人民币、一个私人投资账户、Web 桌面与移动端。
- 期初持仓、手工买卖与费用、应收/实收、标准 CSV、日历、年度统计。
- 不连接券商、不要求证券账户号码；账户只是用户自定义账本名称。
- 复杂公司行动不静默计算：识别后标记待人工调整并暂停受影响期间的自动权益推导。
- 不将自选自动转换为持仓；可从股票详情或自选主动进入录入，数量、成本和日期必须确认。
- 持仓数量不受现有免费 10 个自选额度限制；资源防滥用上限、导入文件大小和频率由服务端配置并明示。

### 1.2 后续范围与进入门槛

P1：未来十二个月现金流、分红质量解释、收入集中度、减派情景、事件提醒、会员分层、多账户。

P2：研究笔记、复利模拟、ETF 分红与基础公司行动、港美股/多币种、OCR、年度报告和移动增强。每项分别评审数据可用性和需求，不将全市场与原生 App 设为首版前置条件。

## 2. 开发前验证（V2-48）

本地技术证据、字段字典、计算算例及仍未通过的业务门槛见 [V2-48 验证报告](V2_48_VALIDATION_REPORT.md)；完成状态仍统一记录于主计划第 20 节。

由产品负责人组织 10–15 位目标用户，研发准备样例和计算器。未经用户授权不向其发送访谈消息或收集真实账单；可使用脱敏或人工构造记录。

访谈围绕现有记账方式、遗漏到账、最难判断的分红风险、维护频率、录入意愿及愿为哪项自动化付费。记录行为与具体困难，不用“你想不想要功能”代替验证。输出用户分层、前三个任务、导入模板需求及首版取舍。

数据验证至少覆盖 30 个事件：年度/中期、同年多次派息、特别分红、预案转实施、延期、更正、取消、日期缺失及历史数据缺口。逐条记录原公告、来源链接、阶段、每股金额、登记/除息/派息日期、抓取时间和差异。

冻结内容：字段字典、事件身份规则、阶段映射、金额单位、历史覆盖范围、更新周期、数据使用条件及带预期输出的算例。日期字段或来源无法可靠取得时，相关自动计算关闭，提供明确的手动待核对模式；不得推算成“已确认”。数据源商用条件由负责人落实，开发记录核实结果，不擅自视为已获授权。

## 3. 账务及计算口径

### 3.1 持仓与成本

- 期初持仓必须有生效日、数量、总成本及历史完整性标记。默认只保证生效日起的历史，不能据此倒推更早的登记日权益。
- 流水至少含事件日期、同日顺序、买/卖/期初/调整/冲正类型、数量、成交价、费用、来源和备注。数量与金额采用 Decimal/Numeric，显示和舍入规则版本化。
- 股数由有效流水重放得到；拒绝超额卖出。历史插入、修改或撤销必须验证后续所有时点，不只检查当前余额。冲正保留原记录及关联。
- 首版成本使用移动加权平均：买入总支出含费用；卖出按原平均成本结转，费用单列。现金分红单列收入，不偷偷冲减买入成本；如提供券商式摊薄成本，必须使用独立名称和公式。
- 总持仓成本、已实现交易盈亏、未实现盈亏和已收股息分别展示。首版不宣传完整组合收益率；资金流或历史不完整时不得显示貌似精确的年化回报。
- 公司行动或持仓调整要记录生效日期、依据和原因；无法确认历史数量时将受影响权益标记待核对。

### 3.2 分红事件与资格

- 事件按稳定外部标识优先识别；没有标识时使用代码、报告期、分红轮次及公告关系人工/规则关联。不要用会更正的日期和金额直接充当唯一身份。
- 保存原始资料、规范化字段和修订历史；同一次方案变更更新版本，同一年度第二次分红创建独立事件。阶段由证据更新，不能按日历到期自动晋级。
- 预案、批准、正式实施、取消等业务阶段与“预计/应收/实收”个人状态分开。只对有实施依据且关键字段完整的事件生成正式应收。
- A 股首版按登记日收盘的有效持仓计算资格。登记日买入/卖出按当日最终持仓反映；登记后卖出不删除已获权益，除息后买入不获得上一事件权益。具体市场规则由 V2-48 样例验证后固化。
- 应收税前金额 = 登记时点合资格股数 × 本次每股现金。保存股数、每股金额、持仓版本和事件版本，按公告/券商精度规则舍入。
- 缺登记日、未知历史、复合分红未拆分或未处理公司行动时，不按当前数量自动生成已确认应收。允许用户补录权益依据，标记为人工确认。
- 事件更正需重算未核对应收；对已核对的记录生成差异待办，保留原始实收及旧计算，不静默改账。取消方案撤销有效待收且保留历史链。

### 3.3 实收、税费与年度归属

- 到预计派息日只生成“待核对”，不自动确认券商已到账。支持部分到账、多笔到账、独立税费/后续补扣、撤销及更正。
- 现金流水记录实际到账日期、原币、税前/税额/净额的已知部分和证据。仅知道净额时税前/税额为空，不用零代替未知。
- 首版税费采用实际录入，不硬编码所有用户统一税率；后续补扣与对应股息关联。核对容差与差额原因可配置并可查。
- “今年已收”按实际到账日统计，税后现金与税前口径分别标明；分红所属财年另列。不得把本年到账的上年度利润分配混称为本年经营产生的分红。
- 未关联现金收入允许先记账，待关联后不得重复计入；分红撤销/核对撤销保留审计，年度总额同步重算。

### 3.4 预测与股息率

| 展示项 | 口径与限制 |
|---|---|
| 已收 | 有实际到账记录的金额，按入账日期 |
| 正式待收 | 正式实施、权益可确定且尚未收齐的余额；不含已收部分 |
| 方案预计 | 预案/批准但未实施等方案推算，明确阶段与持仓不变假设 |
| 历史推算 | 基于普通历史每股分红及当前持仓；披露使用区间和缺失情况，不承诺发生 |
| 未来十二个月 | 截止日之后滚动十二个月；已公布事件覆盖相应历史推算槽位，避免叠加；未知时间列未定月份 |
| 当前价格息率 | 指定期间每股股息 / 指定时点非复权价格；展示 TTM/年度/已公布方案、普通或含特别口径 |
| 成本息率 | 同一股息假设 / 当前剩余持仓单位买入成本；不代表当前市场回报；零或负成本显示不适用 |

所有结果带基准日、数据时间、计算版本和覆盖率。行情更新不能修改真实成交价；报价缺失或过期时持仓股数及收息账本仍可读，市值单独降级。历史推算不能使用未来公告；估算不与实收相加成“实际收益”。

## 4. 数据设计与迁移

V2-50 的账户与隐私基础本地实现见 [ADR-0010](adr/0010-private-portfolio-ownership.md) 和 [交付说明](V2_50_DELIVERY.md)：首版账户元数据、主动确认、本人导出/删除及恢复重放；并未提前实现持仓与交易。

V2-51 持仓交易与重放本地交付见 [ADR-0011](adr/0011-portfolio-ledger-replay.md) 和 [交付说明](V2_51_DELIVERY.md)：新增当前持仓、原始/冲正流水和待核对范围；持仓即时重放，尚无独立缓存表，不提前生成分红应收或实收。

以下为逻辑模型草案，V2-48/49/50 落实时写 ADR 冻结命名与字段类型；不沿用主计划附录 B 的早期用户 UUID 草案，外键须匹配当前用户主键。共享市场数据和私人数据分开。

| 实体（建议名称） | 关键内容与约束 |
|---|---|
| `dividend_events` / `dividend_event_versions` | 标的、外部身份、轮次、报告期、普通/特别、每股金额、阶段、三类日期、公告来源/链接、抓取时间、版本；与旧 `stock_dividends.id` 建映射，重复/歧义不自动合并 |
| `portfolio_accounts` | 当前用户 ID、名称、币种、归档状态、创建时间、版本；首版每用户仅一个活动账户，超额并发由数据库/锁保障 |
| `portfolio_entries` | 账户/标的、类型、日期、顺序、数量、单价、费用、成本、来源批次、幂等键、冲正关联、版本；跨用户关联禁止 |
| `portfolio_positions` | 按账户/标的缓存当前数量、成本、重放版本和历史完整起点；可由流水重建，不作为唯一事实来源 |
| `dividend_entitlements` | 账户/事件/当前计算版本、登记股数、税前应收、计算依据、未知原因、核对状态；历史版本保留，只有一个有效版本 |
| `dividend_receipts` / `receipt_allocations` | 实际日期、金额/税费已知部分、应收分摊、来源与冲正；支持一笔应收多次到账和未关联实收，防重复汇总 |
| `portfolio_import_batches` | 文件摘要、模板版本、校验/确认/提交状态、逐行结果、用户确认、幂等键；不永久保留原始文件 |
| `portfolio_audit_events` | 操作者、对象、变更类型、版本、必要差异、时间；本人数据访问受限，管理员维护访问记录，不写公开运行日志 |
| 后续扩展 | 预测快照、质量评估版本、提醒订阅及去重键、收入目标、研究笔记、公司行动、汇率；按任务增量迁移 |

市场事件对旧 API 采用兼容适配，不做两份可独立修改的事实源。旧分红记录迁移需保留映射、重复检测、数量/金额核对及无法判定清单；先新表回填并对比，切读成功后才考虑清理旧字段。 V2-49 的过渡实现以 [ADR-0009](adr/0009-dividend-event-versions.md) 为准：旧表继续只用于既有研究，新事件层用于核对，二者不可混算；当前只完成增量表、原始观察和未核验旧快照，未进行研究切读，正式切换须另行对账验收。

私人表以用户/账户和日期建索引；数据库约束保证有效唯一性，API 全链路验证所有权。账户归档不等于删除。删除本人账户需明确确认并清理派生结果、待办和导入文件；备份保留及恢复后再删除策略写入隐私说明。

| `/income/receipts` | 待核对、部分到账、实际记录、差异与关联 | 53、55 |
| `/income/analysis` | 未来十二个月、目标、集中度、减派情景 | 57、60 |
| `/stocks/[code]#dividend-quality` | 分红质量、证据和风险变化；从持仓进入时保留返回位置 | 58、59 |

首次进入：说明持仓数据用途 → 建默认账户 → 选择手动或 CSV → 输入带日期的期初/交易 → 展示缺失历史影响 → 生成可确定的应收和不确定清单 → 用户核对首笔到账。

无近期分红时提供“已建立持仓、等待事件”的真实状态，不引导伪造到账。教学样例与私人账户完全隔离，样例操作不计真实激活。

录入/冲正等敏感变更先展示影响和确认；支付返回只恢复表单或页面，不自动写账。表单支持可恢复草稿；URL、浏览器分析和错误上报不携带数量、成本或账户名称。PC 表格最小列宽和不换行标签按既有换行问题回归；移动端用摘要卡片/详情，避免整页横向溢出。加载、空、失败、部分数据与重试均提供独立状态。

## 6. API 与服务边界

沿用 `/api/v1`、现有登录态、统一错误契约和会员能力响应。以下为建议接口，不表示当前已存在：

| 接口组 | 能力 |
|---|---|
| `GET/POST /portfolio/accounts` | 本人账户列表/建立；归档、删除使用明确的对象接口 |
| `GET /portfolio/accounts/{id}/positions` | 数量、成本、行情时间、完整性与计算版本 |
| `GET/POST /portfolio/accounts/{id}/entries` | 查询/提交流水；历史更正使用修订或冲正操作，禁止无痕覆盖 |
| `POST /portfolio/imports/validate`、`/{id}/commit` | 校验生成只读预览，确认后原子提交；校验阶段不写正式流水 |
| `GET /income/calendar`、`/entitlements` | 有界日期范围、本人账户、事件阶段、未知原因 |
| `GET/POST /income/receipts` | 实收/分摊；撤销与更正关联原记录 |
| `GET /income/summary`、`/forecast`、`/risk` | 汇总、预测与风险；高级接口由服务端鉴权 |
| `GET /stocks/{code}/dividend-quality` | 共享证据与质量分析，规则版本及权限边界明确 |
| `GET /portfolio/export` | 本人原始账本及基础结果；分页/异步限制，不收会员费 |

写入接受请求幂等键；重试返回同一结果，键相同而请求不同则冲突。历史更正采用版本校验防止覆盖他人/多窗口修改。并发卖出、账户上限及确认导入在事务内校验。内部重算接口不对普通用户开放。

个人响应使用私有禁止共享缓存策略；缓存键包含所有者、账户、流水版本、事件版本和规则版本。共享股票分析可以缓存，但不得混入个人股数或收入。推荐持仓重放、权益、现金统计、预测和质量规则拆成独立服务，共享明确金额/日期工具，避免把全部逻辑堆入路由。

## 7. 分红质量与个人风险（P1）

### 7.1 分红质量证据

- 5/10 年每股普通分红、特别分红、连续性、减派和断派；年内多次分红先按所属财年/普通口径聚合，再做同口径比较。
- 利润派息率优先使用相同期间普通股现金分红总额 / 同口径归属利润；股本变化时不随意混用每股值与期末股数。
- 工业企业补资本开支与自由现金流；现金覆盖指标必须说明分子分母、期间和计算方式，经营现金流不能冒充自由现金流。
- 金融行业先验证利润、资本约束、资产质量等可得数据；无合适数据时展示“不支持/证据不足”，不硬套工业企业 FCF。
- 分母为零、负利润、异常值、披露滞后和缺失分别解释；先输出可解释结论与证据，不合成无依据的安全评分。
- 规则、阈值、行业映射版本化；先选银行、公用事业、制造业等样本由数据负责人核对，未覆盖行业按已支持证据展示。

### 7.2 个人风险与提醒

股息集中度以同一预测基线为分母，分别展示股票/行业贡献和数据覆盖率；未分类行业单列，未知预测不当零风险。

压力测试支持最大收入来源减派、指定标的减派、剔除特别分红。展示假设、年度金额变化和目标差额；同一事件被多个条件命中时明确合并规则，默认一次覆盖、不重复叠加。

提醒复用现有基础设施，新增方案发布/更正/取消、同口径减派、日期临近、未核对、覆盖恶化等类型。去重键至少覆盖用户、事件/报告、版本、规则和提醒阶段；邮件发送失败可重试但不重复生成站内事件。数据源延迟、补历史和解析失败进入系统数据待办，不当成公司减派消息推送。

## 9. 调度、部署与监控

### 9.1 任务编排

使用现有 GitHub Actions ETL 与 Railway 服务；五分钟行情任务继续独立。V2-48 根据数据源时效确定分红同步频率，首版候选为每个交易日盘后同步、次日上午复查，均使用 Asia/Shanghai 定义调度并转换为实际调度器时区。数据源未达标不宣传实时分红。

分红抓取/规范化 → 事件差异及版本 → 受影响账户重算 → 基础待办/高级提醒。用户提交流水后只重算相关标的和日期范围；批量历史修正异步处理，返回任务状态、旧结果标记及错误重试入口，不让用户以为已更新。

每类任务明确唯一调度入口和锁；Actions 与 Railway 不同时执行同一流水线。采用数据库租约/锁、作业幂等和有界重试；记录耗时、处理数量、失败原因及最后成功时间。补跑不得重复应收、到账或通知，不使用用户公开请求直接触发全市场抓取。

### 9.2 迁移及发布顺序

1. 在临时 PostgreSQL 演练新增迁移、历史回填、约束、重复运行、旧版本兼容及恢复；记录当前 Alembic head，不在计划内硬编码尚未创建的迁移号。
2. 为生产备份并确认恢复演练可用；部署准备阶段核查 Railway/API/Web 的实际配置。现有运维文档存在 Web 托管描述不一致，上线前核实并修正文档，不据旧描述直接操作。
3. 先发布向后兼容的数据库增量与 API，功能开关默认关闭；已有推送会触发自动部署，因此破坏性迁移不得依赖“推送后再手动补表”。迁移入口只运行一次，失败阻止依赖功能开启。
4. 部署 Web 和暂停的新任务；回填共享事件，核对数量、映射、金额及异常清单；用户账本不从自选伪造历史。
5. 内部账号打开 `portfolio_enabled`，核对样本；`income_forecast_enabled`、`dividend_quality_enabled`、`income_risk_alerts_enabled`、`multi_account_enabled` 分别灰度，API 与任务均读取开关。
6. V2-44 事件和 V2-46 降级验收通过后，按白名单 → 小比例稳定分组 → 扩量发布，每级核对账务和数据质量。没有生产证据只标本地完成。
7. 回退优先关开关、停新任务、回滚兼容应用，保留新增数据；避免对有用户流水的生产库直接 destructive downgrade。只在隔离环境演练删表回退，生产恢复采用经过演练的备份/前滚修复。

监控项：事件同步延迟、未知/冲突日期比例、解析错误、重算积压、应收版本冲突、重复事件、核对差异、通知失败、权限拒绝、接口延迟及数据删除失败。账务不一致或越权为立即关闭相关自动写入/高级推送的条件；保留基础只读、数据导出和人工核对路径。

## 10. 测试和上线验收

核心计算用固定算例测试，数据库行为使用真实隔离 PostgreSQL；外部数据源用保存的脱敏快照和契约校验。浏览器测试覆盖 PC 与移动端，不以模拟页面验证替代真实计算验证。

| 场景 | 必须满足 |
|---|---|
| 登记前持 1,000 股，每股派 0.50 元 | 税前应收 500 元，来源和登记数量可追溯 |
| 登记日收盘前买入/卖出 | 分别按最终有效数量计算，不用当前持仓替代 |
| 登记后卖出、除息后买入 | 原持有人应收保留；新买入者不获得旧权益 |
| 期初记录晚于登记日 | 不自动生成历史已确认应收，明确缺失原因 |
| 同一报告期两次派息及重复抓取 | 两个独立事件，重复抓取不增条目 |
| 预案、实施、延期、取消、更正 | 阶段有证据，预计与正式应收不混；实收不可被同步覆盖 |
| 同日流水、历史插入、超额卖出 | 顺序确定；历史修改检查所有受影响余额；并发不产生负仓 |
| 应收 500，实收 300 + 200 | 两笔到账，剩余应收依次为 200、0；汇总不重复 |
| 到账后补扣税、更正和撤销 | 已收按有效实际流水变化，审计链和原归属可查 |
| 已收到未知事件款项后关联 | 关联前后年度已收不增加一次 |
| CSV 重传、重复行、提交超时重试 | 不重复写入；合法同日同额交易可明确确认 |
| 两个用户和两个窗口同时操作 | 不能访问或关联他人对象；版本冲突提示重载 |
| 零/负利润、缺现金流、银行模板 | 明确不适用/证据不足，不误报安全 |
| 实施方案替代历史预测 | 不重复计入；派息日期未知不伪造月度安排 |
| 特别分红及减派情景 | 普通/含特别口径一致，情景冲击不重复应用 |
| 行情过期、数据源失败、公司行动未知 | 账本可读，相关估值或权益明确降级/待核对 |
| 会员到期/试用到期/续费 | 基础账本继续，历史不丢，高级新计算/推送按规则停止/恢复 |
| 迁移、任务补跑、邮件重试 | 旧功能兼容、幂等、可监控和可回退 |
| 免费导出、删除、缓存及日志 | 无公式注入、越权、私人共享缓存或敏感分析事件 |

首版发布须满足：所有固定算例精确一致；至少 30 个来源事件核对通过或明确隔离未支持项；至少 5 套获授权/脱敏的完整账本逐笔核对；关键错误零未解决；迁移、备份恢复、到期降级和开关关闭演练通过。首版白名单可以使用历史真实事件验证，扩大公开灰度前至少观察一次真实分红同步/核对链路，不能用等待日期自动确认到账替代验证。

各任务执行 `pytest`/静态检查及受影响 Web 类型检查、构建和必要 E2E；文档规划阶段只检查内容、链接和任务一致性，不运行无关全量测试。开发交付记录需包含代码提交、测试结果、迁移号、配置开关、任务时区、回填结果、生产版本及走查证据。

## 11. 激活、付费与复盘

复用 V2-44 事件体系。建议服务端事件：`portfolio_created`、`position_recorded`、`import_committed`、`entitlement_generated`、`receipt_confirmed`、`forecast_generated`、`quality_analysis_viewed`、`risk_alert_enabled`；支付交付和续费复用原事件。重试按对象/事件版本去重，样例、内部账号、测试和赠送单排除。

分析平台只发送匿名用户标识、事件类型、功能版本、账户数量分桶、会员状态及设备等必要信息；不发送股票持仓明细、数量、金额、成本、图片或账户名称。业务核对从受权后台读取，不把私人账务明细复制到漏斗系统。

| 指标 | 统计方式 |
|---|---|
| 持仓激活率 | 进入收息引导的真实用户中，7 天内录入至少一个有效持仓的人数占比；只看成熟 7 天 cohort |
| 应收可计算率 | 有相关分红事件的有效持仓用户中，可生成有依据应收的人数占比；同步报告历史不完整及缺字段原因 |
| 核对完成率 | 存在已到预计支付时间待办且完整观察 7 天的用户中，完成核对的比例；不把尚无分红机会用户计作失败 |
| 持续使用 | 激活 cohort 的 7/30 日有效回访，以及下一次真实分红机会后的核对行为；不只统计打开页面 |
| 高级体验到首购 | 首次有效个人高级结果/提醒后 7 天首购人数 / 完整观察 7 天的非付费体验用户；固定样例排除 |
| 续费 | 沿用第 19.7 节同一到期 cohort，展示到期前后 7 天窗口及试用/赠送排除 |
| 信任与成本 | 核对差异原因、纠错时长、导入失败、删除/导出成功率、通知退订、退款及每活跃收息用户的成本 |

先建立至少 14 天稳定技术基线和一个真实收息周期，再与用户访谈一起复盘。少量用户只报告分子分母和具体反馈，不宣称显著提升。价格、免费边界、引导和首页入口分开实验，一次只改一个主要变量。
