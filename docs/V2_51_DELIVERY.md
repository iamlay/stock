# V2-51：期初持仓、交易流水与重算

> 2026-10-27：本地实现与验证，尚未推送或验收生产。前置为 V2-50；不提前开放 V2-52 应收分红或 V2-53 实收核对。

## 功能与计算口径

`/portfolio` 在账户管理下增加持仓和交易模块：支持系统已有 A 股的带日期期初、买入、卖出、人工调整、更正和冲正撤销。人民币单账户、基础维护免费，会员到期或关闭新建开关不冻结本人已有数据。归档账户只读，恢复后可写入。

- 期初明确填写生效日期、数量、总成本及历史完整性（不省略后默认零成本）；必须是该股票第一笔有效流水，不把期初数量倒推到更早日期。
- `since_date` 仅表示用户确认录入起点之后的历史；`incomplete` 表示仍有缺失。起点前始终未知。人工调整强制将历史标为不完整并待核对。
- 买卖填写数量、成交价和本笔全部费用。买入成本增加 `数量 × 价格 + 费用`；卖出按移动加权平均结转成本，已实现盈亏为 `数量 × 价格 − 费用 − 结转成本`。费用另行汇总，但不会重复扣除。
- 调整填写调整后的总数量与总成本（不是差额），必须有原因及依据。调整不伪装成买卖盈亏，不自动处理公司行动。
- 每个股票按 `(生效日期, 同日顺序)` 重放，活跃流水不允许同日顺序重复。界面可指定顺序；数据库写入时间只用于历史列表稳定排序，不决定财务顺序。
- 输入以十进制字符串传输，最多12位整数、6位小数；数据库 `Numeric(20,6)`，计算使用 Decimal 50位上下文。规则版本 `moving-average-cny-v1`：每笔买入成本、卖出结转成本及盈亏按6位小数四舍五入；最后一次清仓结转全部剩余成本，避免尾差残留。平均成本展示6位精度，前端仅移除尾零，不转浮点数。
- 禁止负数量/金额、非有限数、科学计数法、超精度及上海时区未来日期；已知上市日期时禁止更早录入。零持仓调整必须同时为零成本。
- 每次补录、更正、冲正先重放全部有效历史；任一中间时点超卖均整笔拒绝，不仅检查最终余额。
- 当前展示数量、持仓总成本、平均成本、已实现交易盈亏及累计费用。未实现盈亏和已收股息返回 `null`，没有行情时不猜市场价值，不显示组合收益率。

算例：期初100股/1000元，买入100股×20元、费用10元，再卖50股×18元、费用5元，剩150股、成本2257.5元、均价15.05元，已实现盈亏142.5元。

## 不可覆盖的更正链与并发

`portfolio_entries` 保存原始流水。更正是一条关联 `reverses_id` 的新流水；冲正撤销是一条数量和金额为零的 `reversal` 凭据。原记录不改写，最多被直接更正/冲正一次，可继续更正替代记录；撤销替代记录不会复活原记录。需要恢复误撤销内容时新建一笔经完整校验的流水。

所有账户写入保持 `User → PortfolioAccount` 锁序，要求 `expected_version`。流水写入、账户版本递增、最小审计及分红核对范围在同一事务完成。重复 `request_id` + 同内容返回当前快照，不重复记账；同编号换内容拒绝。编号不能跨账户取消其他流水，所有权复合外键也在数据库约束。

持仓从有效流水即时重算，不另建容易失配的持仓缓存；账户版本是当前重放快照版本。当前内测面向手工小账本，全量历史读取，后续大规模导入前需要按实际体量补充分页及性能验证。

`portfolio_review_ranges` 保存每次变动的股票、最早影响日期、账户版本和待核对原因。更正日期前移/后移均取新旧日期较早值，覆盖之后所有潜在登记日。V2-52 必须消费这些范围并核对事件/持仓版本；**本版尚无个人分红记录，因此不会声称已重算或核实分红，更不会写入已确认应收或到账。**

## 隐私、导出与删除

说明版本升级为 `portfolio-ledger-2026-10-27.v2`，scope 为 `private_holdings_and_trades`，列明股票、数量、价格、费用、成本、备注及依据的用途。

旧 V2-50 账户保持原确认记录，不自动扩展授权。首次财务写入前主动勾选并提交当前说明版本及摘要；仅浏览不写确认。拒绝或说明不可用时仍可管理账户、查看和导出已有数据。新建账户确认当前新版说明后可以录入。

- 私人页面继续不加载第三方统计，字段不放 URL、浏览器持久草稿或通用后台审计；财务数字保持字符串。鉴权变化、401、迟到响应和返回缓存沿用 V2-50 清理机制。
- JSON导出升级 `portfolio-ledger-export-v2` / `holdings_and_trades_v2_51`，包含本人账本、完整有效/失效流水及关联、更正原因、持仓快照、核对范围和各版说明确认。CSV在V2-54实现。
- 在线删除和恢复删除清单重放同时清理两张新增私人表。数据库账户删除也级联清理。最小确认和删除凭据继续保留。
- 恢复旧备份时先保持服务隔离/维护，迁移到当前 head，再重放最新独立删除清单并核对，之后才恢复用户访问。创建开关只限制新建，不能代替恢复期间的访问隔离。
- 备份删除清单的独立加密保存和恢复重放仍为运维流程，不能将同库旧备份作为最新删除凭据。详见 [V2-50说明](V2_50_DELIVERY.md#5-备份恢复后重新删除)。

## API

统一前缀 `/api/v1/portfolio`；本人鉴权、无管理员越权、所有响应 no-store，写入继续每用户30次/分钟。

| 方法与路径 | 用途 |
|---|---|
| `POST /accounts/{id}/consent` | `expected_version` + 当前 `consent`，旧账户升级确认 |
| `GET /accounts/{id}/ledger` | 持仓、完整流水、确认状态、规则版本、核对范围 |
| `POST /accounts/{id}/entries` | 原子新增/更正/冲正，返回重算快照 |
| `GET /export` | 免费完整 JSON 导出 |

流水请求示例（`request_id` 每笔新操作使用新的UUID；重试保留原UUID）：

```json
{
  "expected_version": 2,
  "request_id": "c71e667b-b15a-4294-827b-79d095e58419",
  "code": "600036",
  "kind": "opening",
  "event_date": "2025-01-01",
  "day_order": 10,
  "quantity": "100",
  "price": "0",
  "fees": "0",
  "total_cost": "1000",
  "history_status": "since_date",
  "note": "按期初持仓核对",
  "evidence": "",
  "reverses_id": null
}
```

更正保留同股票、传原流水ID和必填原因；撤销使用 `kind=reversal`、原日期及顺序，四个数值为零。日期只接受 `YYYY-MM-DD`，金额仅接受字符串；不接受客户端指定 owner/source/会员字段。
