## 1. 当前能力与边界

新增 `/portfolio` 页面，个人中心有“私人账本”入口。已登录且验证邮箱的用户可在获得内测资格后，主动确认说明并创建一个人民币账户；支持查看、改名、归档、恢复、免费 JSON 导出和明确确认删除。归档不会释放单账户名额，删除后可重新建立不同 ID 的账户。

当前仅存储账户名称、人民币币种、归档/版本及操作时间，不开放持仓、买卖、税费、分红或现金流计算。UI、API capabilities 和导出 scope 均明确这一边界。未创建账户、未确认说明时，浏览不会自动写入私人账户或确认记录。

免费、试用、付费和到期用户可以维护自己的基础数据。账户数据只归本人，普通管理员无 API 读取特权；所有请求均按服务端登录身份查询，不接收所有者或会员字段。导出不会混入其他用户、支付、邮箱、手机号或认证凭证。

## 3. API 契约与缓存

以下路径统一位于 `/api/v1/portfolio`。

| 路径 | 用途 |
|---|---|
| `GET /policy` | 当前说明文本、版本、用途范围和 SHA-256；不需要先授权私人数据 |
| `GET /accounts` | 本人账户、创建开关和单账户上限；无自动创建副作用 |
| `POST /accounts` | 主动确认当前说明后创建；不接受 user_id 和额外字段 |
| `GET /accounts/{id}` | 本人账户信息，其他用户和随机 ID 同为 404 |
| `PATCH /accounts/{id}` | 当前版本号加名称/归档状态，拒绝空改动、null 或跨用户修改 |
| `DELETE /accounts/{id}` | 当前版本号和 `confirmation=DELETE`；同一本人删除请求可安全重试 |
| `GET /export` | 本人账户、操作记录、说明确认及其文本快照，免费 JSON 下载 |

所有成功及业务错误响应使用 `Cache-Control: private, no-store`、`Pragma: no-cache`、`Vary: Authorization, Cookie` 和 `X-Robots-Tag: noindex, nofollow`。校验错误不返回原始 name/body。写入按用户 30 次/分钟、导出 10 次/分钟限流；没有按会员收费。

POST 示例（说明版本和摘要必须来自当前 GET /policy；下方 SHA 为格式占位，不可直接提交）：

```json
{
  "name": "长期收息",
  "currency": "CNY",
  "consent": {
    "accepted": true,
    "version": "portfolio-account-2026-10-27.v1",
    "sha256": "从当前policy响应取得的64位摘要"
  }
}
```

说明过期或账户版本冲突返回 409，前端要求刷新并重新确认，不自动重试写入。更新示例：`{"expected_version":1,"name":"长期账户"}`。删除示例：`{"expected_version":1,"confirmation":"DELETE"}`。UI 还要求用户输入“删除账本”，首次点击删除仅打开确认表单。

导出 scope 为 `account_metadata_only_v2_50`，持仓/交易/自动分红能力为 false；不提供空流水冒充已实现的持仓记账。JSON 保留合法用户文本，避免 CSV 公式执行；名称不出现在下载文件名、查询参数或 URL 中。

## 4. 隐私确认与最小记录

当前说明版本为 `portfolio-account-2026-10-27.v1`，服务端按完整说明内容生成 SHA-256。版本、文本快照和服务端确认时间与账户建立在同一事务写入；未勾选、数字/字符串冒充布尔同意、旧版本和错误摘要均拒绝，不留下确认记录。

操作记录仅保留动作、账户版本、时间及所有权外键，不保存名称前后值，不写通用管理员日志。删除移除在线账户和关联操作记录；最小删除凭据仅含账户 UUID、用户 ID 和删除时间，说明确认只保留版本/文本/确认时间等证明，不包含用户名称。账号注销或进一步个人数据删除须按隐私政策联系核查，不把“删除账本”等同于“所有服务记录及备份立即消失”。

新增持仓、交易等数据范围前需在 V2-51 更新说明和版本，并在首次录入前确认，不能把当前仅账户元数据的授权扩展解释成已授权全部持仓。

## 5. 备份恢复后重新删除

工具：`python -m etl.portfolio_privacy`。仅由有数据库权限的运维在明确环境执行，不提供普通管理员批量清单 API。

```bash
# 从当前数据库导出最新凭据；新文件，0600权限，拒绝覆盖旧文件
python -m etl.portfolio_privacy export-deletions --output etl/out/deletions-2026-10-27.json

# 恢复到隔离库或维护中的目标库后，先 dry-run 再显式 apply
python -m etl.portfolio_privacy replay-deletions --manifest etl/out/deletions-2026-10-27.json
python -m etl.portfolio_privacy replay-deletions --manifest etl/out/deletions-2026-10-27.json --apply
```

操作要求：

- 最新删除清单必须独立于待恢复的旧备份保管；只备份同一数据库中的凭据无法覆盖备份之后发生的删除。
- 清单含最小个人标识，不能上传公开仓库、普通日志或明文 GitHub Artifact。按既有密钥管理和加密备份流程单独加密保管，并验证可解密。`etl/out/` 已忽略，工具不输出用户/账户明细。
- 当前工具不自动向异地存储上传、不设定周期任务；负责人必须在开放内测前落实导出时机、独立保存、权限和恢复核对。源库不可用且缺最新清单时，保持私人功能关闭，核对删除要求后再恢复服务。
- 重放先校验整个清单和所有权；任何匹配冲突拒绝全部操作。默认 dry-run，只在 `--apply` 时删除；没有的旧账户跳过，不删除后来创建的不同 UUID 账户。已清理记录重复重放安全。
- GitHub 现有加密备份 retention 为 14 天；Railway 各备份的实际保留需核实，不能保证所有副本统一 14 天删除。恢复后清理是人工运维流程，不对外宣传已自动同步。
- 未来 V2-51/52 等新私人表必须以账户及用户归属外键关联并级联清理，导出和恢复重放也需相应扩展验证。

## 6. 页面与客户端隔离

私人页动态渲染、noindex、no-referrer。个人中心使用普通链接整页进入，避免把已加载的公共页面统计脚本带入私人文档；根布局在 `/portfolio` 及其子路径不渲染百度和 Vercel 统计。如果仍检测到统计全局或脚本，先刷新文档，再读取私人 API。

名称仅保存在当前页面内存，不存 localStorage/sessionStorage 草稿、不写 URL 或分析事件。认证变化、401、页面进入/退出缓存时清除私人显示；新身份不接收旧身份迟到响应。导出和修改前再次核对当前登录凭证。这里不改变原有登录 token 存储规则。

桌面和手机均可使用。用户未确认说明时不显示名称输入框；取消勾选清除名称草稿。说明获取失败不会阻止已有账户的管理和导出；请求失败、关闭开关、未登录和版本冲突分别提示。
