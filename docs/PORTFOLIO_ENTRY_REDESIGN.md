# 添加持仓重设计：从流水录入转向持仓建档

日期：2026-10-28。状态：原设计规格；核心功能已本地实现，自动历史年均按数据门槛降级，生产/真实样本待验。见[V2-51R交付说明](V2_51R_DELIVERY.md)。参考：用户提供的8张息记截图；现状依据 V2-51 代码。截图中的行情、分红金额和评分只作界面参考，不当作已核实的实时数据或通用券商规则。

交互原型：[添加持仓](prototypes/portfolio-entry.html)。仅演示选择、表单、成本说明和预览；没有真实搜索、行情、分红接口或持久化。

## 1. 结论与范围

默认使用路径改为：**我的持仓 → 添加持仓 → 搜索并选中股票 → 填数量和每股成本 → 核对预览 → 保存**。把持仓建档、记录买卖、历史更正三个任务分开。账户命名/归档/删除移到设置，不再压在持仓列表和录入入口上方。

参考息记的分区、名称搜索、每股成本、成本说明、分红明细和持仓卡片；沿用 StockLab 的米白/深绿风格。不能只换样式或直接复制截图中的计算说明。

本轮设计覆盖：添加已有持仓、新买入、成本口径、列表与详情、历史分红参考和预测设置、分组、校验、数据迁移及验收。按阶段实现；未完成的数据能力不显示成0。首期继续A股人民币，ETF单列下一阶段，基金、港美股、自定义资产不放假入口。股票分红档案可以进入；稳定性评分和定投回测不塞进添加表单。

## 2. 当前问题与证据

| 现状 | 影响 | 改造 |
|---|---|---|
| `portfolio-ledger.tsx` 手填6位代码，没有名称联想 | 需要记代码，错股风险高 | 搜索名称/代码，必须选中明确标的；修改搜索文字立即清除旧标的绑定 |
| 一个类型下拉框含期初、买、卖、调整、冲正 | 普通用户先学会账务概念才能建仓 | 独立“已有持仓 / 新买入”入口；持仓卡片内记录卖出；修正放详情 |
| 期初只收总成本 | 用户通常知道券商显示的每股成本，易把单价填成总额 | 默认每股成本，自动计算总额；高级选项可按总额录入，保留输入精度 |
| 默认展示同日顺序，默认值10 | 同股同日第二笔会冲突；用户不应理解内部序号 | 服务端事务中分配稳定顺序；必要时展开“调整当天先后顺序” |
| 全部按移动加权平均；输入非负 | 摊薄成本与分红摊薄成本不能正确表达；负成本被拒绝 | 成本口径明确保存，允许合法有符号净投入，绝不将负数塞进加权持仓成本 |
| 期初日期与成交日期共用一个控件 | 当前快照容易被当成历史交易/登记日持仓 | 已有持仓使用“持仓截至日期”；新买入使用“成交日期” |
| 期初后 `realized_pnl/fees` 从0开始 | 容易被误读为全部持有历史的实际盈亏/费用为0 | 标注“记账起点后”；起点前未知保持未知 |
| 持仓卡仅代码，缺市值和股息参考 | 保存后感受不到收息管理价值 | 名称、数量、行情时间、市值、明确口径的成本和分红参考 |
| 源数据和个人账本尚未连通 | 不能可靠输出年分红及股息收入 | 已实施历史、正式应收、实际到账、历史情景严格分层 |

现有 Decimal、全历史超卖校验、版本锁、幂等、追加式更正、隐私隔离继续保留。已有357项测试证明已定义的V2-51行为通过，不证明产品已经覆盖用户的券商成本口径。

## 3. 页面结构与用户任务

### 3.1 我的持仓

顶栏：账本选择（首期单账本）、“添加持仓”、设置。资产概览：有可靠行情的已知市值、记账起点后已实现盈亏、已确认实收、历史分红参考；未开放/缺数据分别显示“暂未开放 / 数据不足”。部分标的无报价时显示“已知市值”及缺失数量，不冒充总市值。

卡片：名称+代码+市场、数量、最新价及行情时间、市值、所选成本口径+每股成本、历史年分红参考、当前价格股息率；可自定义排序、按分组查看。默认收起零持仓，保留“已清仓”入口。

动作：买入、卖出、查看记录；更正和删除进入详情。移动端卡片与底部添加按钮；PC端表格/卡片加侧栏编辑。退出未保存表单有提示，但私人草稿只在内存保存，切换账号和离开页面按既有隐私策略清理。

### 3.2 添加持仓：两个入口

- **录入已有持仓（默认）**：适合把券商当前持仓搬进来，不需要补全多年买卖。
- **记录一笔买入**：适合刚成交的交易，进入数量、成交价和费用表单。

已有同股票时提示“已持有N股”：提供“记录一笔买入 / 修正当前持仓 / 取消”，不默默叠加第二条期初。修正属于显式快照替代/调整，预览影响，不覆盖旧记录。

### 3.3 区块一：选择股票

搜索框“输入股票名称或代码”，输入后约250ms防抖；结果显示名称、代码、市场和币种。Enter选中高亮项，鼠标/触屏一次选择成功；异步旧搜索结果不能覆盖新结果。清空或修改搜索文字取消绑定。网络失败提供重试，不留下看似选中的旧标的。

搜索独立于高股息筛选、是否有最新行情及研究榜单；已有退市/停牌持仓仍可维护，明确标记状态。未收录标的提示暂不支持，不自动创建错误证券。空态可提供本人自选和已有持仓快捷入口。

选中后显示固定标的摘要卡和“分红档案”入口；查看档案后返回保留当前内存表单。换股保留数量/价格需再次确认，默认清空与原标的有关的费用、成本及预测设置，防错填。

### 3.4 区块二：录入已有持仓

| 字段 | 默认/规则 | 解释 |
|---|---|---|
| 持仓数量 | 必填，>0；A股录入整数股，允许非整手持仓 | 不要求历史持仓凑100股；ETF将以独立单位规则处理 |
| 持仓截至日期 | 必填，默认今日，上海时区，不晚于今日 | 明确“该日收盘/日终的持仓快照”；当日尚未完成交易时提示使用上一已核对日或等交易完成后确认 |
| 成本口径 | 首次必须选择，无静默默认 | 分红摊薄 / 摊薄成本 / 加权平均 / 不确定 |
| 当前每股成本 | 元/股，必填；按所选口径校验 | 支持切换输入总额，实时显示数量×单价，但不把舍入后的显示单价倒算回原始总额 |
| 分组 | 可选，未分组 | 与自选分组独立；不要求先建组 |
| 备注 | 可选，折叠 | 不要求账户号码、证件、券商密码 |

已有持仓的成本视为截至日所选口径的**已含历史影响的余额**，不再加一笔“交易费用”，防止重复计费。历史累计买入、卖出、实收仅放在可选的“补充历史”，明确哪些金额已体现在期初成本中，不作为新增交易或到账再次入账。

“不确定”允许保存数量与原始参考成本，标记 `reported_unknown`；禁算依赖成本口径的盈亏、成本股息率。用户确认口径后补全，不强制猜测。

可选首次买入日期仅作备忘，未知可留空；不能据此生成期间持仓轨迹或历史分红资格。

### 3.5 区块二：记录一笔买入

股票、成交日期、买入股数、成交价必填；费用可选。显示“成交金额 / 费用 / 总支出”。空费用按“暂按0估算，待补充”标记，主动填0才是已知为0；不硬编码券商费率。成交价不能用当前行情自动充当历史成交价。

默认追加到当日已录流水之后；只有会造成当日超卖时提示检查当天顺序，可调整到特定交易之前/之后。服务端分配顺序并持有账户锁，不靠前端猜序号。预览会显示买入后的数量、已知成本指标及影响范围。

卖出从持仓详情进入，选中股票只读；数量不可超过相应历史时点可用股数。继续验证后续全部历史余额。

### 3.6 区块三：历史分红参考（可选，不阻塞保存持仓）

选项：过去12个月 / 过去36个月年均 / 过去60个月年均 / 自定义。用户可跳过，个人设置跟随持仓保存；历史记录/解释基础免费，高级情景和目标规划仍归V2-57/62。

明确显示基准日、时间窗口、年度每股参考值、按当前股数估算的年度金额、记录明细及数据完整性；标注“历史情景，假设持仓不变，不是应收或承诺”。与真实已收和正式待收分开。

历史明细包含所属报告期、除息日、每股税前现金、方案阶段与来源。截图中的年度/中期金额与股价不直接导入项目数据库。特别分红默认单列并不进入普通分红参考，可明确勾选纳入。

### 3.7 区块四：保存前预览

展示：标的、录入方式、日期语义、数量、成本口径、每股成本、对应总额、费用是否已含/是否未知、历史覆盖、分红参考依据。

文案示例：“截至2026-10-28持有中国神华1000股，分红摊薄成本20.00元/股，已回收资金后的剩余净投入20000.00元。此前买卖与分红未补齐，不计算历史已实现盈亏。”

预览不创建流水或同意记录；保存检查账户版本与预览版本、当前数据说明，冲突要求重新核对。提交中禁重复点击，网络重试用同一个请求UUID。成功返回持仓列表并高亮新卡片，可继续添加下一只。

## 4. 成本口径：分开存储，不能凭按钮互相转换

定义（仅在历史完整、无未处理公司行动时）：Q=剩余数量，B=累计买入支出含费用，S=累计卖出净收入，D=累计实际净到账分红（扣税更正后）。下面定义为本项目规则，不宣称所有券商相同。

| 指标 | 算法 | 可否负数 | 使用目的 |
|---|---|---|---|
| 加权持仓成本 Cw | 买入增加实际支出；卖出按卖出前平均成本结转 | 否，可为0 | 持仓成本和交易盈亏 |
| 交易后剩余净投入 Ct | B−S | 可为0或负数 | 不计分红的资金回收情况，界面可简称“摊薄成本” |
| 含分红剩余净投入 Cd | B−S−D | 可为0或负数 | 含真实到账分红的回收情况，界面可简称“分红摊薄” |
| 对应每股值 | 各自余额÷Q，Q>0才计算 | 随对应余额 | 每股展示；清仓显示— |

费用：买入费进入B/Cw，卖出费从S扣减；不能同时扣收入又作为额外成本二次扣。现金分红仅改变Cd和实收统计，不改Cw。累计应收/预测不是D。

例（忽略费用，使用截图中的教学算例，不是实时投资数据）：买1000股×5元，卖500股×8元，已收净股息500元；剩500股。Cw=2500（5元/股），Ct=1000（2元/股），Cd=500（1元/股），已实现交易盈亏1500元。

**已有持仓只知道一种口径时，只有对应期初余额已知。** 例如录入分红摊薄1元×500股，仅知道Cd0=500，不能推导Cw0、Ct0、历史实现盈亏及过去实际收息。其他口径显示“需补充历史”，不能切换标签后继续显示同一个数。

在快照之后：Cw0已知才能按移动加权计算卖出成本与交易盈亏；Ct0已知按新买入支出/卖出净收入更新；Cd0已知再扣快照之后的实际净到账。用户后来补录快照之前的交易/分红时，必须选择“补充历史并重新建立基准”或“仅补充历史资料（已包含在基准）”，原子预览去重，不重复扣减期初。

负成本：保留符号；提供“示例：−2.00元/股表示已回收资金超过原投入”，不增加一个可与数字矛盾的“负成本”复选框。Cw可为0（经明确确认的零成本持仓），不接受负数。Ct/Cd<=0时股息率不做除零/负分母，展示“净投入已回收”；这不代表该股票没有风险。

清仓：保留该持仓周期的历史盈亏和净回收，不显示每股成本；再次买入默认创建新持仓周期，旧周期收益不自动摊到新周期。跨周期汇总在详情独立展示。部分转出、送转及其他公司行动未支持时要求核对，不当成卖出收益。

## 5. 日期和历史边界决定准确性

已有持仓快照是截至日**日终**状态。当日交易已体现在快照中，不允许再按快照后新交易追加同日买卖造成双计；同日补历史需显式替代快照并重新预览。新交易从次日开始。后续可以扩展有时区的日内快照，但本版不假装精确到日内。

不能把“最早买入日期”当作快照生效日；也不能凭今天的1000股推算去年登记日有1000股。对于快照日登记资格，必须有覆盖登记时点的用户确认依据并满足V2-52规则；否则待核对，不自动认领当日分红。快照之前一律未知，后续同日买卖按稳定顺序重放。用户提供的日期是否真实，不由系统自行假定。

已有V2-51期初按原规则解释，保留 `rule_version` 和日期语义，不默默改成新版日终快照；新版本用独立事件/基准类型。

## 6. 预测、股息率和价格

- 历史参考按明确滚动窗口 `(基准日−12/36/60个月, 基准日]` 内的已实施、可核对现金分红，以除息日归窗；报告期仅展示，不混入除息年度。N年窗口总额÷N，同一方案各版本去重，同一年多次现金派息均计入。
- **完整覆盖且确实无分红才是0**；缺数据、日期缺失、来源仅预案、历史不满窗口、无法统一拆并股后的每股口径均为“不足以计算”，不自动换更久年份、不按实际有分红的年份缩小分母。
- 自定义数值允许0，非负、明确“税前年每股估计”，保留设置时间、操作者、来源user_estimate；不写公共分红事件、不生成实收。可以在历史数据不足时使用，但不伪装成系统核实。
- 年度参考金额=当前Q×年度每股参考。不会因为用户选择12个月就认定过去12个月已实际收到这些钱；没有持股资格和到账数据时不计算个人历史收入。
- 当前价格股息率=年每股参考÷有效最新价；展示行情时点和估计口径。加权成本股息率仅在Cw已知且>0时计算，名字与当前价股息率分开。用Ct/Cd作分母的比例另称“剩余净投入分红比例”，不混称投资收益率。
- 行情缺失显示—；过期行情显示实际日期，不贴“实时”。报价币种/标的需一致。初版不计算回本年限/回本进度；缺少历史总投入时无法得出完整回本进度。
- “分红稳定性70分”“覆盖率100%”等需要独立证据和可复算定义，不能照搬截图数字。档案首期展示已核对事实，后续按V2-58/59实现质量与风险解释。

## 7. 技术改造边界

保留：账户所有权、复合外键、私有no-store、默认灰度开关、免费导出删除、声明式确认、追加更正和历史重放。

新增/调整设计对象（具体表名在实现ADR冻结）：

- `position_baseline`：account/owner/instrument、basis、signed_amount、original_input_mode/value、quantity、as_of_date、as_of_semantics、history_coverage、周期ID、rule_version；按口径存已知性，不用0代替未知。原始券商展示成本作为reference保留，未知口径不自动进入计算。
- `position_preferences`：分组、主展示口径、预测窗口/自定义值、基准/版本；只改展示偏好不能重写历史。
- `position_cycle`：明确清仓再建仓边界和可知历史，后续实际到账保留原权益周期归属。
- `cost_projection`：并行计算Cw/Ct/Cd，输出known/unknown/estimated、缺失原因与规则版本；不简单放宽原 `PortfolioEntry.total_cost>=0` 约束。V2-51流水财务字段保持原含义。
- 受保护的股票搜索：返回instrument身份、名称/市场/币种/状态，不依赖高股息或价格筛选；不把私有搜索意图和草稿发送第三方统计。
- `preview` / `confirm`：服务端Decimal校验与试算；确认关联原预览、账户版本、规则和数据版本。候选排序/分组不引起财务重算，真实账务更正才产生分红核对范围。
- 费用已知性、财务字段nullable与期间标签进API契约；前端只做格式展示，不以JS浮点决定账务值。
- 搜索、表单、成本帮助、分红档案、持仓卡片、交易详情拆为独立组件；不继续扩张单个`PortfolioLedger`。
- 股数精度依资产类型校验，新A股入口整数股；旧版可能已有小数股，迁移保留并标记待核对，不静默取整。

兼容迁移：既有数据标记legacy规则、默认加权展示，保留所有原数值和版本；可确定的完整交易周期可重建多口径，否则只保留已知的加权口径。旧期初不自动推算累计买入/卖出/实收。新增数据范围再次版本化说明；新增表纳入本人导出、账户删除、恢复清单重放和跨用户约束。迁移只增量，不强制覆盖现有持仓。

## 8. 开发顺序及验收门槛

在V2-52前插入V2-51R系列，避免在错误输入语义上继续生成权益。

| 任务 | 交付 | 验收 | 粗估人日 |
|---|---|---|---|
| V2-51R1 | 名称/代码选股；已有持仓/新买入分流；单价/总价及预览；自动同日排序；持仓首页 | 选择一次成功；不能绑定旧搜索结果；分清日期与费用；主流程无流水类型和技术序号 | 3–5 |

| V2-51R3 | 历史分红参考和明细、自定义情景、行情卡片、分组 | 完整零/缺数区分；窗口/去重/特别分红/行情日期验证；不生成应收实收 | 3–5 |

## 9. 必须通过的验收样例

1. 输入“中国神华”或601088可选中同一标的；更改文字后不能把旧标的提交；弱网乱序返回不覆盖新结果。
2. 已有1000股、加权成本20元/股→总成本20000；按总额20000录入也一致，不把20当作总成本。
3. 仅知500股、分红摊薄1元/股→Cd=500，Cw/Ct及起点前盈亏/实收未知；切换加权不显示1元假值。
4. 完整教学算例三口径分别5/2/1元，交易盈亏1500，手续费各扣一次。
5. 500股、分红摊薄−2元→Cd=−1000；允许保存，比例显示净投入已回收，不显示负股息率或无穷大。
6. 截至日已含历史分红500，再补历史资料500不二次扣；次日实际新到账100才再扣100，冲正恢复100。
7. 仅输入当前快照和首次买入日期，不能自动生成过去权益；快照日已含交易不能再叠加。
8. 同股同日录两笔买入自动排序；跨标签并发仍幂等/防覆盖；历史超卖继续拒绝。
9. 过去36个月数据完整、仅两年派息，仍按3年均值；缺一年数据不当作零；未实施预案不入历史参考。
10. 特别分红开关和自定义值可追溯，不改变真实股息记录；有送转但无法统一每股口径时历史参考阻断。
11. 清仓后每股成本为—，保留历史；重新买入新周期不被旧盈利自动冲成负成本。
12. 持仓导出/删除/恢复重放覆盖新对象；跨账号、401、返回缓存仍清理私有展示和草稿。
13. 旧版小数股和期初日期原样保留；新整数规则不能导致旧数据静默丢失。
14. PC与手机完成同一主路径，错误定位到字段，帮助弹层关闭保留输入，最终确认前不产生财务写入。
